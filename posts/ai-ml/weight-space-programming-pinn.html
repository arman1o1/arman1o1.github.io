Weight-Space Programming on Physics Neural Networks: Can an LLM Read and Write PDE Weights?

November 13, 2026 • ☕ 10 min read

Yesterday I read Sparks of Weight-Space Programming by Rikiya Takehi, Jayden Teoh, Alex Zhang, and Omar Khattab, and immediately wanted to test the same idea on physics networks. Their headline result was wild: frontier LLMs reading raw neural weights without forward passes, writing MinAtar and Go agents from scratch without gradients, and patching 0.016% of Qwen3.5-0.8B to fix reasoning loops.

Physics-Informed Neural Networks (PINNs) are a much cleaner laboratory for testing whether an LLM genuinely understands weight-space geometry. Unlike a 270M-parameter transformer, a standard 1D PDE solver (2 -> 32 -> 32 -> 1 with tanh) has only 1,185 parameters, smooth differential structure, and exact analytical solutions to score against. So I wired up a three-part benchmark against Gemini 4 Carbon (with automatic fallback to Gemini 4 Argon on 180s timeouts) to see where native weight-space programming actually works – and where it breaks.

0. Experimental Setup & Baselines

Every task uses the exact same PhysicsMLP architecture: Linear(2, 32) -> Tanh -> Linear(32, 32) -> Tanh -> Linear(32, 1), taking $[x, t] \in [0, 1]^2$ and outputting scalar $u(x, t)$. All 1,185 weights easily fit inside context as raw JSON.

Three Benchmark PDEs on $(x, t) \in [0, 1] \times [0, 1]$
$$\begin{aligned} \textbf{Heat:} \quad & u_t = 0.05\,u_{xx}, \qquad u(x,0) = \sin(\pi x) + 0.5\sin(3\pi x), \qquad u(0,t)=u(1,t)=0 \\ \textbf{Wave:} \quad & u_{tt} = u_{xx}, \qquad u(x,0) = \sin(\pi x), \; u_t(x,0)=0, \qquad u(0,t)=u(1,t)=0 \\ \textbf{Advection:} \quad & u_t + 0.5\,u_x = 0, \qquad u(x,0) = \sin(2\pi x), \qquad u(0,t)=u(1,t) \end{aligned}$$

For the gradient-descent baseline, I trained each network on CPU for 1,500 Adam steps (512 interior collocation points, 128 IC points, and 128 BC points per step). Notice that 1,500 steps of Adam already gets wave down to 0.025 relative $L^2$ error, while advection still struggles at 0.231 because periodic travelling waves are notoriously finicky for small tanh MLPs early in training.

1. Writing Weights Zero-Shot: Direct JSON vs. Analytical Compiler

I tested two strict zero-shot writing protocols (zero training data, zero gradients, zero forward passes, and AST-verified to ban lstsq, polyfit, minimize, or autograd):

  • Direct JSON (zero_shot_json): Emit all 1,185 floating-point numbers directly in one JSON response.
  • Analytical Weight Compiler (zero_shot_code): Write a pure math/numpy Python function build_weights() that derives the weights analytically from the PDE's structure.

Look at that advection compiler result: 0.001483 relative $L^2$ error and 0.000000 PDE residual – 156x more accurate than 1,500 steps of Adam, with zero data and zero gradients. What made it work is genuinely clever. Instead of hand-guessing numbers, Gemini 4 Argon noticed that $\frac{d}{dz}[\frac{1}{2}\tanh(\alpha(z - z_k))] = \frac{\alpha}{2}\operatorname{sech}^2(\alpha(z - z_k))$ acts as a smooth Dirac delta along the characteristic coordinate $z = x - 0.5t$. It then computed the exact Fourier transform of $\operatorname{sech}^2$ and divided its quadrature weights by $\hat K(2\pi)$ to deconvolve the smoothing kernel!

💻 Python: Gemini 4 Argon's Deconvolved sech² Quadrature Compiler for 1D AdvectionPython 
import math
import numpy as np


def build_weights() -> dict[str, list]:
    N = 32
    z_min, z_max = -0.65, 1.15
    dz = (z_max - z_min) / (N - 1)
    z_nodes = [z_min + i * dz for i in range(N)]
    alpha = 1.4 / dz

    w0 = np.zeros((N, 2), dtype=np.float64)
    b0 = np.zeros(N, dtype=np.float64)
    for k in range(N):
        w0[k, 0] = alpha
        w0[k, 1] = -0.5 * alpha
        b0[k] = -alpha * z_nodes[k]

    # Deconvolve finite-width sech^2 kernel at frequency omega = 2*pi
    omega = 2.0 * math.pi
    xi = (math.pi * omega) / (2.0 * alpha)
    deconv_factor = math.sinh(xi) / xi

    c = np.zeros(N, dtype=np.float64)
    for k in range(N):
        weight_factor = 0.5 if (k == 0 or k == N - 1) else 1.0
        c[k] = 0.5 * omega * math.cos(omega * z_nodes[k]) * dz * weight_factor * deconv_factor

    val_at_quarter = sum(c[k] * math.tanh(alpha * (0.25 - z_nodes[k])) for k in range(N))
    C_offset = 1.0 - val_at_quarter

    # Distributed linear pass-through in Layer 2 via small-signal scaling eps
    eps = 1e-3
    w2 = np.zeros((N, N), dtype=np.float64)
    b2 = np.zeros(N, dtype=np.float64)
    for j in range(N):
        w2[j, :] = eps * c
        b2[j] = eps * C_offset

    w4 = np.full((1, N), 1.0 / (N * eps), dtype=np.float64)
    b4 = np.zeros(1, dtype=np.float64)
    return {
        "net.0.weight": w0.tolist(), "net.0.bias": b0.tolist(),
        "net.2.weight": w2.tolist(), "net.2.bias": b2.tolist(),
        "net.4.weight": w4.tolist(), "net.4.bias": b4.tolist(),
    }

The failures on wave and heat are just as revealing. Notice how wave got pde_residual_mse = 0.0 in both Direct JSON and Compiler mode yet scored l2_rel_error = 1.125. Why? Because any sum $f(x - t) + g(x + t)$ satisfies $u_{tt} - u_{xx} = 0$ identically by d'Alembert's theorem – the model locked onto the exact characteristic rays $w_t = \pm w_x$, then flipped a sign when matching the boundary/initial amplitude. On heat, it even derived a 4-point second-difference bilinear multiplier around the inflection bias $b_{\text{opt}} = \operatorname{asinh}(1/\sqrt{2})$ (where $\tanh'''(b_{\text{opt}}) = 0$) to multiply $f(x) \cdot g(t)$ inside a tanh layer, though its hand-estimated temporal decay knots drifted (0.715 error). Direct JSON without code fared worst across the board: LLMs reason far better when compiling weights symbolically in Python than when emitting 1,185 raw floats as tokens.

2. Read-Only Weight Forensics (Zero Forward Passes)

Next, I flipped the problem around. I took the three Adam-trained PINNs, stripped all names and metadata, randomly permuted the hidden neurons in layers 0 and 2 (which preserves $f(x, t)$ while destroying neuron ordering), and handed model_alpha, model_beta, and model_gamma to Gemini 4 Carbon with strict instructions: zero forward passes, classify which weights belong to Heat, Wave, and Advection, and cite the mechanistic evidence.

Gemini 4 Carbon nailed 3/3 (100% accuracy, 0.99 confidence on all three) in 127.7 seconds. Even with randomly shuffled neurons, the PDE physics leaves an unmistakable geometric fingerprint in $(w_x, w_t)$:

3. Surgical Weight-Space Patching (And Where It Struggled)

Finally, I tested whether an LLM could repair a broken PINN in one shot by editing strictly fewer than 5% of weights ($\lt 59$ of 1,185 parameters). I injected a localised defect into the clean Adam wave PINN (l2_rel_error = 0.0252): I shifted net.4.bias by +0.55 and inverted-and-doubled net.0.weight[idx, 1] ($w_t$) on the two largest-norm Layer-0 neurons, blowing the $L^2$ error up to 5.2504. Then I gave the corrupted weights plus a single $9 \times 3$ diagnostic snapshot to the model.

Gemini 4 Carbon timed out at 180s here, and the fast fallback (Gemini 4 Argon, 7.23s) immediately spotted and reversed the exact +0.55 shift in net.4.bias (-0.044), cutting the error from 5.25 down to 3.67. However, without running intermediate probes (like the 10–50 forward passes Takehi et al. allowed in their Qwen3.5-0.8B experiment), it misattributed the remaining temporal asymmetry to seven weights in net.4.weight instead of tracing the defect upstream to the two flipped net.0.weight[:, 1] rows.

Takeaways for Weight-Space Programming

Even on a tiny 1,185-parameter network, three clear rules stood out from running this end-to-end:

  1. Symbolic compilers beat raw weight tokens. Asking an LLM to emit 1,185 floats directly in JSON fails badly, whereas letting it write a 40-line numpy compiler produced 0.001483 $L^2$ error on 1D advection – beating 1,500 Adam steps by two orders of magnitude.
  2. Reading weights is already surprisingly reliable. Identifying Heat vs. Wave vs. Advection with 3/3 accuracy from shuffled raw matrices works because PDE symmetries and characteristic velocities ($w_t / w_x$) live directly in the geometry of $W_0$ and $W_2 W_0$.
  3. One-shot patching breaks when defects sit behind mixing layers. Detecting an output bias offset is trivial from one snapshot, but localising a flipped neuron two layers deep without any forward-pass budget is where zero-feedback debugging hits a wall.
