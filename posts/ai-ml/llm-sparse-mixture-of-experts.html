Sparse Mixture-of-Experts (MoE): Routing Math, Load Balancing & Expert Parallelism

November 8, 2026 • ☕ 15 min read

In a dense Transformer, knowledge capacity and computational cost are rigidly coupled: every token $x_t$ must pass through 100% of the Feed-Forward Network (FFN) parameters, costing $2 N_{\text{param}}$ FLOPs per token. Sparse Mixture-of-Experts (MoE) decouples total model capacity ($N_{\text{total}}$) from active per-token compute ($N_{\text{active}} \ll N_{\text{total}}$) by replacing each dense FFN with $E$ distinct SwiGLU expert sub-networks and activating only the top-$K$ experts per token.

Yet training a 671B-parameter MoE (like DeepSeek-V3, which activates only 37B parameters per token across 256 routed experts) introduces three formidable systems and optimization challenges: routing collapse (where the router sends 99% of tokens to 2 experts), auxiliary gradient interference, and distributed All-to-All communication stragglers. Here is the complete mathematical and pure-PyTorch reference to modern MoE engineering.

0. From Coarse Top-2 MoE to Fine-Grained + Shared Experts

Classical MoE architectures (Switch Transformer, Mixtral 8x7B) split the FFN into a small number of coarse experts ($E = 8$, $K = 2$). Modern frontier MoEs (DeepSeekMoE, Qwen-2.5/3-MoE) introduce two structural innovations:

  1. Dedicated Shared Experts ($E_s$): Always-active experts that process every token deterministically ($g_{\text{shared}} \equiv 1$), capturing universal syntax and common world facts so routed experts don't waste capacity duplicating shared transformations.
  2. Fine-Grained Routed Experts ($E_r \gg 8$): Splitting each expert's intermediate dimension $d_{\text{ffn}}$ by $m$ while multiplying both total experts ($m E_r$) and active experts ($m K$). Increasing combinatorial selection from $\binom{8}{2} = 28$ to $\binom{256}{8} \approx 4.1 \times 10^{14}$ combinations enables surgical domain specialization at identical FLOPs.
Fine-Grained + Shared Expert MoE Layer Output
$$y_t = h_t + \underbrace{\sum_{j=1}^{E_s} \text{SwiGLU}_j^{(S)}(h_t)}_{\text{Always-Active Shared Experts}} + \underbrace{\sum_{i \in \text{TopK}(s_t, K)} g_{t,i} \, \text{SwiGLU}_i^{(R)}(h_t)}_{\text{Sparse Routed Experts } (K \ll E_r)}$$

where $\text{SwiGLU}_i(h) = \bigl(\text{SiLU}(h W_i^{\text{gate}}) \odot (h W_i^{\text{up}})\bigr) W_i^{\text{down}}$, $s_{t,i}$ is the affinity score between token $h_t$ and expert centroid $e_i$, and $g_{t,i}$ is the normalized routing weight.

Figure 1: DeepSeek-V3 MoE architecture combining always-active Shared Experts with Fine-Grained Routed Experts and Auxiliary-Loss-Free dynamic bias $b_i$. Note that $b_i$ shifts Top-$K$ selection indices while the forward gate weight uses the pure affinity $s_{t,i}$.

1. Classical Load Balancing: Switch Auxiliary Loss & Router $z$-Loss

Without load balancing, early random advantages cause a handful of experts to receive larger gradients, making them even more preferred by the router until $E - K$ experts die completely. Fedus et al. (2022) introduced the Switch Auxiliary Load-Balancing Loss, which penalizes the dot product between the empirical fraction of tokens $f_i$ dispatched to expert $i$ and the mean router probability $P_i$ allocated to expert $i$ across a batch of $T$ tokens:

Switch Auxiliary Loss & ST-MoE Router $z$-Loss
$$f_i = \frac{E_r}{K T} \sum_{t=1}^{T} \mathbb{I}\!\left(i \in \text{TopK}(p_t, K)\right), \qquad P_i = \frac{1}{T} \sum_{t=1}^{T} p_{t,i}, \qquad \mathcal{L}_{\text{aux}} = \alpha_{\text{aux}} \sum_{i=1}^{E_r} f_i \cdot P_i$$ $$\mathcal{L}_{z} = \frac{c_z}{T} \sum_{t=1}^{T} \left( \log \sum_{i=1}^{E_r} \exp(z_{t,i}) \right)^2$$

Why multiply $f_i \cdot P_i$? Because the step indicator $f_i$ is non-differentiable ($\nabla_\theta f_i = 0$), multiplying it by the differentiable probability mean $P_i$ provides a straight-through gradient $\frac{\partial \mathcal{L}_{\text{aux}}}{\partial P_i} = \alpha_{\text{aux}} f_i$ that pushes down the logits of overloaded experts. Using Cauchy-Schwarz / Lagrange multipliers under $\sum_i f_i = E_r / K \cdot K = E_r$ and $\sum_i P_i = 1$, $\sum_i f_i P_i$ is uniquely minimized at $1.0$ when $f_i = 1$ and $P_i = 1 / E_r$ (uniform load). Meanwhile, $\mathcal{L}_z$ (Zoph et al., 2022) penalizes the squared logsumexp of raw router logits $z_{t,i}$, preventing exponential BF16 roundoff instabilities.

2. Auxiliary-Loss-Free Load Balancing (DeepSeek-V3)

The fundamental flaw of $\mathcal{L}_{\text{aux}}$ is gradient interference: if a batch contains 80% Python code tokens, those tokens should naturally route to coding experts, yet $\mathcal{L}_{\text{aux}}$ injects strong gradients into the backbone weights forcing Python tokens into poetry or translation experts just to flatten $f_i$. Increasing $\alpha_{\text{aux}}$ balances hardware load at the cost of degraded language modeling perplexity.

DeepSeek-V3 (Wang et al., 2024) eliminates $\mathcal{L}_{\text{aux}}$ from the main objective by introducing a non-gradient per-expert bias vector $b \in \mathbb{R}^{E_r}$ used solely inside the Top-$K$ selection operator:

Auxiliary-Loss-Free Biased Selection & Unbiased Gate Aggregation
$$\mathcal{I}_t = \text{TopK}\!\Bigl(\bigl\{s_{t,i} + b_i\bigr\}_{i=1}^{E_r},\; K\Bigr), \qquad g_{t,i} = \begin{cases} \dfrac{s_{t,i}}{\sum_{j \in \mathcal{I}_t} s_{t,j}} & \text{if } i \in \mathcal{I}_t \\ 0 & \text{otherwise} \end{cases}$$ $$b_i \leftarrow b_i + \gamma_{\text{bias}} \cdot \text{sign}\!\left(\bar{c} - c_i\right), \qquad \text{where } c_i = \sum_{t=1}^{T} \mathbb{I}(i \in \mathcal{I}_t), \quad \bar{c} = \frac{K T}{E_r}$$

Crucially, $b_i$ adjusts which $K$ experts are chosen (via dual-ascent sign updates with step size $\gamma_{\text{bias}} = 0.001$), while the actual gating weight $g_{t,i}$ uses the unbiased sigmoid affinity $s_{t,i} = \sigma(h_t^\top e_i)$. Thus, zero load-balancing gradients ever pollute the language modeling weights!

import torch
import torch.nn as nn
import torch.nn.functional as F

class ClassicalTopKRouter(nn.Module):
    """Switch / Mixtral Top-K Softmax Router with Auxiliary Load-Balancing Loss and Router z-Loss."""
    def __init__(self, d_model: int, num_experts: int = 8, top_k: int = 2, alpha_aux: float = 0.01, c_z: float = 1e-3):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        self.alpha_aux = alpha_aux
        self.c_z = c_z
        self.gate = nn.Linear(d_model, num_experts, bias=False)

    def forward(self, h: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor, torch.Tensor]:
        # h: [T, d_model]
        logits = self.gate(h.float())                           # [T, E] in FP32 for stability
        probs = F.softmax(logits, dim=-1)                       # [T, E]
        topk_probs, topk_idx = torch.topk(probs, self.top_k, dim=-1)
        gates = topk_probs / topk_probs.sum(dim=-1, keepdim=True).clamp(min=1e-12)

        # 1. Switch Auxiliary Load-Balancing Loss: E * sum(f_i * P_i)
        one_hot = F.one_hot(topk_idx, num_classes=self.num_experts).float()  # [T, K, E]
        f_i = one_hot.mean(dim=(0, 1)) * self.num_experts                    # [E], mean is 1.0
        P_i = probs.mean(dim=0)                                              # [E], sum is 1.0
        aux_loss = self.alpha_aux * (f_i * P_i).sum()

        # 2. Router z-Loss: c_z * mean(logsumexp(logits)^2)
        z_loss = self.c_z * (torch.logsumexp(logits, dim=-1) ** 2).mean()
        return gates.to(h.dtype), topk_idx, aux_loss + z_loss, f_i.detach()

class AuxLossFreeRouter(nn.Module):
    """DeepSeek-V3 Auxiliary-Loss-Free Router with Sigmoid Affinity & Dynamic Bias Update."""
    def __init__(self, d_model: int, num_experts: int = 16, top_k: int = 4, gamma_bias: float = 0.01):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        self.gamma_bias = gamma_bias
        self.centroids = nn.Linear(d_model, num_experts, bias=False)
        self.register_buffer("expert_bias", torch.zeros(num_experts))

    def forward(self, h: torch.Tensor, update_bias: bool = True) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
        # 1. Unbiased sigmoid affinity s_{t,i}
        scores = torch.sigmoid(self.centroids(h.float()))       # [T, E]

        # 2. Biased Top-K selection: argtopk(s_{t,i} + b_i)
        biased_scores = scores + self.expert_bias.unsqueeze(0)
        _, topk_idx = torch.topk(biased_scores, self.top_k, dim=-1)  # [T, K]

        # 3. Gather UNBIASED scores for forward gating weights!
        unbiased_topk = torch.gather(scores, dim=-1, index=topk_idx)
        gates = unbiased_topk / unbiased_topk.sum(dim=-1, keepdim=True).clamp(min=1e-12)

        # 4. Compute token load per expert and update bias without gradients
        counts = torch.bincount(topk_idx.view(-1), minlength=self.num_experts).float()
        mean_count = counts.mean()
        if update_bias and self.training:
            with torch.no_grad():
                self.expert_bias.add_(self.gamma_bias * torch.sign(mean_count - counts))

        load_ratio = counts / mean_count.clamp(min=1e-6)
        return gates.to(h.dtype), topk_idx, load_ratio.detach()

3. Expert Parallelism (EP), Capacity Factor & All-to-All Dispatch

When $E_r = 256$ experts are distributed across $P_{\text{EP}}$ GPUs ($E_{\text{local}} = E_r / P_{\text{EP}}$ experts per GPU), executing an MoE layer requires two global All-to-All network collectives per layer:

  1. Permutation & All-to-All Dispatch: Sort local tokens by target expert ID, send tokens to the GPU hosting their assigned expert ($\text{Volume} = B S_{\text{local}} K d_{\text{model}} b_{\text{bytes}}$).
  2. Grouped GEMM Execution: Execute all $E_{\text{local}}$ SwiGLU experts in a single fused Grouped GEMM kernel over variable-sized token buckets.
  3. All-to-All Combine & Un-permutation: Return expert outputs back to each token's originating GPU and accumulate weighted sum $\sum_{k=1}^K g_{t, k} y_{t, k}$.
Expert Buffer Capacity & Token Dropping Bound
$$C_{\text{expert}} = \left\lceil \text{CF} \cdot \frac{T \cdot K}{E_r} \right\rceil$$

In static-shape frameworks (TPUs / Megatron-Core with pad-to-capacity), each expert allocates a fixed tensor buffer of $C_{\text{expert}}$ tokens controlled by Capacity Factor $\text{CF} \in [1.0, 1.25]$. Any token routed to an expert after its buffer reaches $C_{\text{expert}}$ is dropped (passed directly through the residual connection $y_t = h_t$).

Figure 2: Distributed Expert Parallelism (EP) execution flow. Tokens are sorted by expert assignment, dispatched across GPUs via `All-to-All`, processed via Grouped GEMM, and returned via a second `All-to-All` combine.
PyTorch Implementation: Complete Fine-Grained + Shared Expert MoE Layer with Capacity DispatchPure PyTorch 
import math
import torch
import torch.nn as nn
import torch.nn.functional as F

class SwiGLUExpert(nn.Module):
    def __init__(self, d_model: int, d_ffn: int):
        super().__init__()
        self.w_gate = nn.Linear(d_model, d_ffn, bias=False)
        self.w_up = nn.Linear(d_model, d_ffn, bias=False)
        self.w_down = nn.Linear(d_ffn, d_model, bias=False)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # x: [num_tokens, d_model] -> [num_tokens, d_model]
        return self.w_down(F.silu(self.w_gate(x)) * self.w_up(x))

class DeepSeekStyleMoELayer(nn.Module):
    """
    Combines always-active Shared Experts with Fine-Grained Routed Experts,
    Aux-Loss-Free dynamic bias routing, and optional Capacity Factor token dropping.
    """
    def __init__(
        self,
        d_model: int = 128,
        d_expert: int = 64,
        num_shared: int = 1,
        num_routed: int = 8,
        top_k: int = 2,
        capacity_factor: float | None = None
    ):
        super().__init__()
        self.num_routed = num_routed
        self.top_k = top_k
        self.capacity_factor = capacity_factor

        self.shared_experts = nn.ModuleList([SwiGLUExpert(d_model, d_expert * 2) for _ in range(num_shared)])
        self.routed_experts = nn.ModuleList([SwiGLUExpert(d_model, d_expert) for _ in range(num_routed)])
        self.router = AuxLossFreeRouter(d_model, num_experts=num_routed, top_k=top_k)

    def forward(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        B, S, D = x.shape
        h = x.view(-1, D)  # [T, D] where T = B * S
        T = h.size(0)

        # 1. Shared Experts (always active on all T tokens)
        y_shared = sum(exp(h) for exp in self.shared_experts)

        # 2. Routed Experts with Aux-Loss-Free dynamic bias
        gates, topk_idx, load_ratio = self.router(h)  # gates, topk_idx: [T, K]
        y_routed = torch.zeros_like(h)

        # Optional capacity cap C = ceil(CF * T * K / E)
        max_cap = math.ceil(self.capacity_factor * T * self.top_k / self.num_routed) if self.capacity_factor else T

        for e_idx, expert in enumerate(self.routed_experts):
            token_indices, k_positions = torch.where(topk_idx == e_idx)
            if token_indices.numel() == 0:
                continue
            if token_indices.numel() > max_cap:
                token_indices = token_indices[:max_cap]
                k_positions = k_positions[:max_cap]

            expert_in = h[token_indices]
            expert_out = expert(expert_in)
            weights = gates[token_indices, k_positions].unsqueeze(-1)
            y_routed.index_add_(0, token_indices, expert_out * weights)

        out = (h + y_shared + y_routed).view(B, S, D)
        return out, load_ratio

4. Failure Modes & MoE Systems Diagnostics

1. Synchronous Straggler Effect Under Imbalanced Routing: Because `All-to-All` Combine is a collective barrier across all $P_{\text{EP}}$ GPUs, overall step latency is dictated by the single most overloaded GPU: $T_{\text{step}} \propto \max_{i} c_i$, not the mean $\bar{c}$! If one expert receives $4\times$ average load, 7 out of 8 GPUs sit completely idle at the barrier.
Fix: Track $\text{MaxVio} = \frac{\max_i c_i - \bar{c}}{\bar{c}}$ at every step, use Aux-Loss-Free bias updates ($\gamma_{\text{bias}} = 10^{-3}$), and apply Node-Limited Routing (restricting each token to at most $M = 4$ physical nodes so cross-node IB traffic is strictly bounded).
2. Router Precision Instability in BF16: Computing router logits $h_t^\top e_i$ and `softmax`/`sigmoid` in BF16 causes tie-breaking oscillations and sudden expert swaps during training.
Fix: Always cast $h_t$ and router weights $e_i$ to FP32 for the gating linear layer and normalization before casting gating weights $g_{t,i}$ back to BF16.
DeepSeek-V3 Config
$E_s = 1$ shared expert, $E_r = 256$ routed experts, $K = 8$ active per token ($671\text{B}$ total, $37\text{B}$ active).
Bias Update $\gamma_{\text{bias}}$
$\gamma_{\text{bias}} = 0.001$ for the first 14.3T tokens, frozen to $\gamma_{\text{bias}} = 0.0$ for the final 500B tokens to prevent late-stage oscillation.
DualPipe Overlap
Overlaps `All-to-All` dispatch/combine of micro-batch $b$ over InfiniBand with Tensor Core computation of micro-batch $b-1$, hiding $\gt 95\%$ of EP communication latency.

5. Runnable End-to-End Verification: Proving Aux-Loss-Free Load Convergence

The runnable script below initializes an `AuxLossFreeRouter` with skewed expert centroids (where Expert 0 initially captures disproportionate load) and runs dynamic bias updates, verifying that load violation converges smoothly while leaving language-model gradients 100% uncorrupted.

Runnable Verification Script: Aux-Loss-Free Convergence & MoE Forward/BackwardVerified PyTorch 
import torch

def verify_moe_stack():
    torch.manual_seed(42)
    T, d_model, E, K = 512, 64, 8, 2

    # 1. Skew router centroids so Expert 0 & 1 dominate initially
    router = AuxLossFreeRouter(d_model=d_model, num_experts=E, top_k=K, gamma_bias=0.02).train()
    with torch.no_grad():
        router.centroids.weight.data[0] += 0.75
        router.centroids.weight.data[1] += 0.50

    h = torch.randn(T, d_model)
    _, _, initial_load = router(h, update_bias=False)
    initial_max_vio = initial_load.max().item()

    # Run 60 steps of Aux-Loss-Free dynamic bias updates (zero weight gradients!)
    for _ in range(60):
        _, _, final_load = router(torch.randn(T, d_model), update_bias=True)
    final_max_vio = final_load.max().item()
    assert final_max_vio < 1.30 and final_max_vio < initial_max_vio, "Bias routing failed to balance load!"

    # 2. Verify Classical Router Aux + z-Loss vs Full DeepSeekStyleMoELayer backward pass
    classical = ClassicalTopKRouter(d_model=d_model, num_experts=E, top_k=K)
    gates_c, idx_c, reg_loss, _ = classical(h)
    assert gates_c.shape == (T, K) and reg_loss.item() > 0.0

    moe_layer = DeepSeekStyleMoELayer(d_model=d_model, d_expert=32, num_shared=1, num_routed=E, top_k=K, capacity_factor=1.25)
    x_batch = torch.randn(4, 32, d_model, requires_grad=True)
    out, load_ratio = moe_layer(x_batch)
    out.sum().backward()
    assert out.shape == x_batch.shape and x_batch.grad is not None

    print(f"[PASS] Skewed Initial Max Load Ratio   : {initial_max_vio:.2f}x mean load (Imbalanced)")
    print(f"[PASS] Post-Bias Update Max Load Ratio : {final_max_vio:.2f}x mean load (Balanced with ZERO aux grad!)")
    print(f"[PASS] Full DeepSeek MoE Layer Grad    : Verified shape {tuple(out.shape)}, input grad norm {x_batch.grad.norm().item():.2f}")

if __name__ == "__main__":
    verify_moe_stack()
